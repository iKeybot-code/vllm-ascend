1.1 MHA — Multi-Head Attention（标准多头）

每个 Query 头拥有独立的 Key 和 Value 头。KV Cache 显存与 num_heads 成正比。

MHA：4 个 Query 头对应 4 组独立 KV，KV Cache 占用最大。

1.2 MQA — Multi-Query Attention

所有 Query 头共享 1 组 Key/Value。KV Cache 显存降至 MHA 的 1/num_heads，但质量有所下降。

1.3 GQA — Grouped-Query Attention

Query 头分组，每组共享一组 KV。是 MHA 与 MQA 的折中方案，vLLM 默认路径。

1.4 MLA — Multi-head Latent Attention（DeepSeek）

将 KV 压缩到低秩 latent 向量再展开，大幅降低 KV Cache 大小。同时用解耦 RoPE 维持位置编码。

MLA：KV Cache 中只存低秩压缩向量 c_KV（kv_lora_rank 维），而非完整多头 K/V，显存大幅下降。Decode 时再 up-project 还原。

KV Cache 大小对比（seq_len=4096, head_dim=128, 32 头）：
  • MHA: 4096 × 32 × 128 × 2 ≈ 32 MB / 层
  • MQA: 4096 × 1 × 128 × 2 ≈ 1 MB / 层
  • GQA (8 kv头): 4096 × 8 × 128 × 2 ≈ 8 MB / 层
  • MLA (kv_lora=512): 4096 × 512 × 1 ≈ 2 MB / 层（+ RoPE 部分）

2. FlashAttention 计算流程

核心FlashAttention 通过 tiling（分块） 将 Q、K、V 切成小块，在 SRAM 中完成 attention 计算，避免在 HBM 中物化完整的 N×N attention matrix。

关键点：FlashAttention 的核心是 online softmax（分块 softmax）——在 SRAM 中对每个 tile 计算 S_ij = Q_i · K_j^T 后立即更新局部最大值与累加和，最终合并得到完整 softmax 结果，无需物化 N×N 矩阵。vLLM 使用 flash_attn_with_kvcache 接口在 decode 时直接传入 page table 进行块状 KV 读取。

3. PagedAttention 结构与计算逻辑

vLLM 核心PagedAttention 将 KV Cache 组织为固定大小的 block，通过 block table 映射逻辑序列到物理 block，类似操作系统的虚拟内存分页机制。

5. Prefix Cache 查询 / 命中 / 加载 / 驱逐逻辑

核心机制Prefix Cache 复用已计算的 KV Cache。当新请求的 prompt 前缀与已缓存 block 的内容匹配时，直接引用已有物理 block，跳过 prefill 计算。

5.3 驱逐 (Eviction) 逻辑详解

vllm-ascend 中的对应状态：
  • PrefillCacheHit — 前缀命中，复用已有 block，仅计算剩余 token
  • PrefillNoCache — 无命中或纯新 prompt，全量 prefill
  • DecodeOnly — Decode 阶段，每个请求 1 个 token
  • Block manager 在 allocate_slots() 中先查 prefix cache，命中则 ref_count += 1
  • 请求完成后 free() 将 ref_count -= 1，降为 0 时加入 LRU evictable 队列
