1. 概述

vLLM 作为当前主流的大模型推理引擎，其核心竞争力之一在于对 Attention 计算的深度优化。 本报告系统梳理 vLLM（含 vllm-ascend NPU 插件）中涉及的主要 Attention 技术，包括： 基础多头注意力变体、PagedAttention、FlashAttention 系列、Chunked Prefill、投机解码、 Prefix Caching、Sliding Window、MLA、稀疏 Attention、Decode Context Parallelism、量化 Attention 以及 Cross Attention。 每个技术均给出原理说明、典型使用场景及在 vllm-ascend 中的关键代码位置。

计算优化

FlashAttention、MLA、DSA/SFA 通过算子融合、KV 压缩、稀疏选择降低显存与计算量。

调度优化

PagedAttention、Chunked Prefill、Prefix Caching 提升批次利用率与 KV Cache 复用。

并行优化

Decode Context Parallelism (DCP)、Sequence Parallelism 分散长序列 decode 压力。

硬件适配

vllm-ascend 针对昇腾 NPU 提供 FIA、PA、FA3、SFA、DSA 等 NPU 原生算子路径。

2. Attention 基础架构

2.1 标准 Multi-Head Attention (MHA)

MHA 是 Transformer 的原始注意力形式。每个 token 的 Query、Key、Value 被投影到多组头空间， 每组头独立计算 Scaled Dot-Product Attention，最后拼接并投影输出。

Attention(Q, K, V) = softmax(QKT / √dk) V

在 vLLM 中，MHA 仍是通用后端（如 CUSTOM backend）的基础假设。 vllm-ascend 的 AscendAttentionBackendImpl 默认按 num_heads / num_kv_heads 计算 num_queries_per_kv，兼容 MHA 与 GQA/MQA。

2.2 Multi-Query Attention (MQA)

MQA 让多个 Query 头共享同一组 Key/Value 头（num_kv_heads = 1）， 显著降低 KV Cache 显存占用与内存带宽压力，是长上下文 decode 的重要优化。

2.3 Grouped-Query Attention (GQA)

GQA 是 MHA 与 MQA 的折中：Query 头被划分为若干组，每组共享一个 KV 头 （1 < num_kv_heads < num_heads）。vLLM 的多数模型默认走 GQA 路径， vllm-ascend 的 FIA/PA 算子均通过 num_key_value_heads 参数支持 GQA。

代码关联：在 AscendAttentionBackendImpl.__init__ 中， 通过 self.num_queries_per_kv = self.num_heads // self.num_kv_heads 统一处理 MHA/GQA/MQA 的重复广播逻辑。

3. PagedAttention

核心创新 PagedAttention 是 vLLM 成名的关键技术。它将 KV Cache 组织为固定大小的 block（默认 128 tokens）， 通过逻辑 block table 将非连续的物理 block 映射到每个请求的逻辑序列， 从而消除内存碎片、支持动态扩缩容，并允许不同请求共享同一段物理 KV。

3.1 核心思想

  • Block 化：KV Cache 不再按连续大 tensor 分配，而是拆成 [num_blocks, block_size, num_kv_heads, head_size]。
  • Block Table：每个请求维护一张逻辑到物理 block 索引表。
  • Copy-on-Write：共享 block 在需要写入时被复制，保证解码正确性。
  • Decode 优化：Decode 阶段每个请求仅生成 1 个（或少量）新 token，适合按 block 索引直接读取历史 KV。

3.2 vllm-ascend 中的实现

vllm-ascend 在 decode-only 且满足形状条件时，会调用昇腾 NPU 的 _npu_paged_attention 算子。 该算子直接以 block table 和 context lens 为输入，跳过显式构造大 KV tensor 的过程。 

# vllm_ascend/attention/attention_v1.py
def forward_paged_attention(self, query, attn_metadata, output):
    torch_npu._npu_paged_attention(
        query=query,
        key_cache=self.key_cache,
        value_cache=self.value_cache,
        num_kv_heads=self.num_kv_heads,
        num_heads=self.num_heads,
        scale_value=self.scale,
        block_table=attn_metadata.block_tables,
        context_lens=attn_metadata.seq_lens,
        out=output,
    )
    return output

# Graph capture 路径使用 full_graph_pa 保存 workspace 与 handle
def full_graph_pa(self, query, attn_metadata, output):

3.3 启用条件

using_paged_attention() 函数决定是否走 PA 路径，排除条件包括： 启用投机解码、A5 设备、非 FULL_DECODE_ONLY graph 模式、当前 batch shape 不在 pa_shape_list 内。

4. FlashAttention 系列

FlashAttention 通过分块（tiling）和重计算（recomputation）在 SRAM 中完成 Attention 计算， 避免构造巨大的 N×N attention score matrix，显著降低 HBM 读写量。

4.1 FlashAttention / FlashAttention-2

  • 减少 HBM 访问量，支持 causal mask 与任意序列长度。
  • 在 vLLM 中常以 FLASH_ATTN backend 形式存在，v1 与 v0 架构均有对应实现。

4.2 FlashAttention-3 (FA3)

FA3 针对 Hopper 等新一代 GPU 优化，但在 vllm-ascend 中， AscendFABackend 通过 flash_attn_npu_v3 库在 NPU 上提供类似语义的实现。 它调用 flash_attn_with_kvcache，支持 page table、cumulative seqlens、causal 等参数。 

# vllm_ascend/attention/fa3_v1.py
class AscendFAImpl(AscendAttentionBackendImpl):
    def _flash_attn_with_kvcache(self, query, block_table, actual_seq_lengths,
                                  seq_lens, is_causal, max_seq_len):
        attn_output = _fa3_fn(
            query,
            key_fa_blk, value_fa_blk,
            cache_seqlens=seq_lens,
            page_table=block_table,
            cu_seqlens_q=actual_seq_lengths,
            max_seqlen_q=max_seq_len,
            causal=is_causal,
            ...
        )
        return attn_output

4.3 Fused Infer Attention (FIA) — 昇腾原生

vllm-ascend 默认 backend CUSTOM 实际调用的是昇腾 npu_fused_infer_attention_score 系列算子， 包括 V1 与 V2。它同时覆盖 prefill、decode、chunked prefill、sliding window 等多种场景， 输入布局采用 TND（token、head、dim），通过 actual_seq_lengths 描述变长序列。 

# vllm_ascend/attention/attention_v1.py forward_fused_infer_attention
torch_npu.npu_fused_infer_attention_score(

    block_size=block_size,

    num_key_value_heads=self.num_kv_heads,
    num_heads=self.num_heads,
    scale=self.scale,
    sparse_mode=3,  # causal
    ...
)

4.4 Sliding Window Attention (SWA)

当模型配置 sliding_window 时，FIA 使用 sparse_mode=4 与 pre_tokens=sliding_window 限制每个 token 只能 attend 到左侧固定窗口内的 KV，降低长序列 decode 的内存与计算。

5. Chunked Prefill (SplitFuse)

调度核心 Chunked Prefill 将长预填充请求切分成多个 chunk，与 decode 请求混合调度到同一个 batch 中执行， 从而避免单个长 prefill 阻塞所有 decode 请求，提升整体吞吐。

  • 同一 batch 内可能同时存在 decode token 与 prefill token。
  • 需要构造特殊的 attention mask，让 prefill chunk 只能看到已生成的历史 tokens。
  • 在昇腾 A5 上，当混合 prefill/decode 时会拆成两次 FIA 调用分别执行。
# vllm_ascend/attention/attention_v1.py _forward_fia_chunked_prefill_split
if is_950() and attn_metadata.attn_state == AscendAttentionState.ChunkedPrefill \
        and attn_metadata.num_decodes > 0 and attn_metadata.num_prefills > 0:
    return self._forward_fia_chunked_prefill_split(...)

AttentionMaskBuilder.get_splitfuse_attn_mask() 提供 2048×2048 的上三角 mask， 用于 chunked prefill 场景。

6. 投机解码 (Speculative Decoding)

投机解码通过小模型（draft）快速生成候选 token，再由大模型（target）一次验证多个 token， 在 accept 率较高时可显著降低每个有效 token 的平均延迟。

6.1 Attention 层面的变化

  • Decode 阶段每个请求可能一次性处理多个候选 token（num_speculative_tokens > 1）。
  • decode_threshold 被调整为 1 + num_speculative_tokens，且不能超过 16。
  • 需要为 draft 模型单独捕获 graph 参数（get_draft_graph_params）。

6.2 vllm-ascend 中的投机路径

AscendAttentionState.SpecDecoding 标记投机状态。 在 graph replay 更新时，attn_keys 可能需要按 layer 索引重排， 并对 draft 模型的多步 metadata 进行循环展开。

注意：当启用投机解码时，using_paged_attention() 会返回 False， 即投机场景不走 NPU PagedAttention，而走 FIA 路径。

7. Prefix Caching

Prefix Caching 对输入 prompt 的公共前缀进行 KV Cache 复用。vLLM 的 block manager 会追踪每个物理 block 的 hash， 当新请求前缀命中已缓存 block 时，直接复用而无需重新计算。

  • 命中缓存时，Attention 状态为 PrefillCacheHit。
  • 未命中或纯新 prompt 时为 PrefillNoCache。
  • Decode 阶段为 DecodeOnly。

在 vllm-ascend 中，AscendAttentionMetadataBuilder 根据 common_attn_metadata.attn_state 选择不同的 block_table 与 seq_lens 处理路径；_get_fia_params 针对 PrefillNoCache、PrefillCacheHit、DecodeOnly 分别构造 key/value 视图与 block table。

8. Multi-head Latent Attention (MLA)

模型级优化 MLA 是 DeepSeek-V2/V3 等模型引入的注意力压缩技术。它通过低秩压缩将 Key/Value 投影到一个小的 latent 空间， 大幅降低 KV Cache 大小，同时通过解耦 RoPE 保持位置编码能力。

8.1 核心思想

  • Q 侧压缩：Query 先投影到低秩空间 q_lora_rank，再恢复到多头。
  • KV 侧压缩：Key/Value 共享一个 kv_lora_rank 的 latent vector，仅保留独立的 RoPE 部分。
  • Cache 形状：从 [seq_len, num_kv_heads, head_size] 变为 [seq_len, kv_lora_rank]，显存显著下降。

8.2 vllm-ascend 中的 MLA 后端

vllm-ascend 提供专门的 ASCEND_MLA backend，实现类为 AscendMLAImpl， metadata builder 为 AscendMLAMetadataBuilder。 当开启 Decode Context Parallelism 时，会切换为 AscendMlaDCPImpl / AscendMlaDCPMetadataBuilder。 

# vllm_ascend/attention/mla_v1.py
class AscendMLABackend(AttentionBackend):
    def get_name(self): return "ASCEND_MLA"
    def get_impl_cls(self):
        if enable_dcp(): return AscendMlaDCPImpl
        return AscendMLAImpl
    def get_kv_cache_shape(...):
        return num_blocks, block_size, num_kv_heads, head_size

8.3 自定义算子封装

vllm_ascend/ops/mla.py 中的 AscendMultiHeadLatentAttention 包装了上游 MLAAttention，并通过 torch.ops.vllm.mla_forward 自定义算子 在 NPU 上执行前向，支持 TP gather、KV cache 等逻辑。

9. 稀疏 Attention

针对超长上下文，稀疏 Attention 通过选择性地只 attend 到关键 KV，进一步降低计算与显存。 vllm-ascend 中主要有两条路径：SFA 与 DSA。

9.1 SFA (Sparse Flash Attention)

ASCEND_SFA backend 用于支持 DeepSeek-V4 等模型的稀疏 MLA。 它维护 top-k 稀疏索引，将 KV 分为常驻（resident）与离载（offload）两层， 在 decode 时仅加载必要的 top-k KV block。 

# vllm_ascend/attention/sfa_v1.py
class AscendSFABackend(AttentionBackend):
    def get_name(self): return "ASCEND_SFA"
    def get_impl_cls(self):
        if sparse_kv_offload: return AscendSFAKVOffloadImpl
        if dcp: return AscendSFADCPImpl
        return AscendSFAImpl

9.2 DSA (DeepSeek Sparse Attention / Dynamic Sparse Attention)

ASCEND_DSA backend 在 vllm_ascend/attention/dsa_v1.py 中定义， 主要用于 DeepSeek-V4 的稀疏注意力。它通过压缩、Hadamard 变换、压缩 mask 等技术， 在 prefill 阶段对 KV 进行压缩，decode 阶段按压缩后的索引进行稀疏注意力计算。

  • _npu_flash_attention_v3 支持 mask_type=MASK_TYPE_NORM_COMPRESS_SELF_ATTENTION 等压缩 mask。
  • DSA 可与 DCP 结合，形成 AscendDSACPImpl。

10. Decode Context Parallelism (DCP)

DCP 将长序列的 decode 阶段 KV 沿序列维度切分到多个 TP/DP 组上并行计算， 每个 rank 负责一段 local KV，最后通过 all-gather / reduce-scatter 合并结果。 它主要解决超长上下文 decode 时单个 rank KV 放不下的问题。

10.1 vllm-ascend 中的 DCP 实现

  • 普通 Attention：AscendAttentionDCPImpl / AscendAttentionDCPMetadataBuilder
  • MLA：AscendMlaDCPImpl / AscendMlaDCPMetadataBuilder
  • SFA：AscendSFADCPImpl / AscendSFADCPMetadataBuilder
  • DSA：AscendDSACPImpl / AscendDSACPMetadataBuilder

当 parallel_config.decode_context_parallel_size > 1 时， enable_dcp() 返回 True，各 backend 自动切换到 DCP 实现。

11. 量化 Attention

量化 Attention 主要关注 KV Cache 的 INT8/FP8 压缩，以降低长上下文下的显存占用。 vllm-ascend 提供 AscendC8AttentionBackendImpl 处理 C8（per-channel INT8）KV cache。

11.1 C8 KV Cache 路径

  • 在 prefill 阶段将 key/value 量化为 INT8 并写入 KV cache。
  • decode 阶段通过 antiquant scale 反量化后参与 FIA 计算，或使用 NZ 5D 布局直接传入 antiquant 参数。
  • 通过 key_antiquant_scale / value_antiquant_scale 等参数与 FIA 融合。
# AscendC8AttentionBackendImpl 示例
extra_args = {
    "key_antiquant_scale": layer._c8_k_aq_scale_nz_bnsd,
    "value_antiquant_scale": layer._c8_v_aq_scale_nz_bnsd,
    "key_antiquant_mode": 0,
    "value_antiquant_mode": 0,
    "inner_precise": 1,
}

12. Cross Attention / Encoder-Decoder

在 encoder-decoder 模型与 VL 模型中，decoder 需要 attend 到 encoder 的输出（如图像编码、源语言文本）。 vllm-ascend 通过 AttentionType.ENCODER_DECODER 与 AttentionType.ENCODER_ONLY 区分因果自注意力与双向交叉注意力。

  • ENCODER_ONLY 使用无因果 mask 的 npu_fusion_attention。
  • ENCODER_DECODER 的 prefill 阶段，actual_seq_lengths_kv 使用 torch.cumsum(seq_lens) 构造。
  • pooling 模型走 _forward_encoder_attention 分支。

14. 总结

vLLM 的 Attention 体系可以概括为“一个通用后端 + 多个专用后端 + 硬件原生算子”：

  1. 通用后端 AscendAttentionBackend 通过 FIA 算子覆盖绝大多数场景；
  2. PagedAttention 在 decode-only 且满足条件时提供极致性能；
  3. FlashAttention-3 作为可选高性能路径；
  4. MLA/SFA/DSA 针对 DeepSeek 等模型做结构级压缩与稀疏优化；
  5. DCP 将超长序列 decode 压力分散到多 rank；
  6. Chunked Prefill + Prefix Caching + Speculative Decoding 在调度层进一步提升吞吐与延迟；
  7. 量化 Attention 与 Cross Attention 覆盖生产环境中的显存与多模态需求。

理解这些技术之间的组合关系（例如 MLA + DCP + Chunked Prefill）， 是进行 vLLM/vllm-ascend 性能调优与问题定位的关键。
