② 八阶段逐层解析

1 API Server 入口 上游复用

  • FastAPI/Quart HTTP Server (上游)

  • Tokenizer 编码 → prompt_token_ids (上游)
  • AsyncLLM.add_request() (上游)

2 Block Hash 链 上游复用

  • Request.block_hasher 按 hash_block_size 切片 (上游)
  • 链式 SHA256: hash1 = sha256(hash0 + t128..t255) (上游)
  • 一旦某 hash 不匹配后续必不匹配 → break (上游)

  • RecomputeScheduler(Scheduler) (自维护)

  • Part B: waiting 队列 prefix cache 查找 (自维护)
  • _get_computed_blocks_for_connector PD 增强 (自维护)

  • get_kv_cache_coordinator 工厂被 Patch 替换 (自维护)
  • AscendHybridKVCacheCoordinator 不动点迭代 (自维护)
  • CompressAttentionManager 逻辑块哈希 (自维护)
  • BlockPool / get_cached_block / cache_full_blocks (上游)

5 Slot Mapping 完全自定义

  • AscendBlockTables.compute_slot_mappings (自维护)

  • NPU 优化: 整块加载 + tl.gather + CP interleaving (自维护)

6 异步队列 上游框架 + 自维护回调

  • waiting / running / skipped_waiting (上游结构)
  • WAITING_FOR_REMOTE_KVS 状态 (上游)
  • _update_waiting_for_remote_kv 回调 (自维护)
  • partial-group hit 回退逻辑 (自维护)

7 Prefill / Decode 上游框架 + 继承

  • NPUModelRunner(GPUModelRunner) (继承)
  • model.forward() 各层计算 (上游模型实现)

⑤ 核心结论

Prefix Cache 的基础设施（hash 链、BlockPool、KVCacheManager、Scheduler 框架、KVConnector 协议）完全复用上游。

vllm-ascend 的自维护集中在 3 个 NPU 专属扩展点：

  • 压缩 MLA 逻辑块哈希 — CompressAttentionManager 按 block_size × compress_ratio 聚合，避免物理块级误命中
  • 多 group 不动点迭代 — AscendHybridKVCacheCoordinator 跨 MLA/SWA 组协调 cache hit 长度，支持 partial-group hit
  • PD 分离 KV Transfer 链路 — 本地 + 远端双重 prefix cache 查找 + 异步加载回调 + Mooncake/AscendStore 传输

外加 NPU 专属的 BlockTable/Triton slot_mapping kernel 和 KV Cache Spec 扩展。
